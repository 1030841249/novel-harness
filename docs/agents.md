# Agent 体系

> novel-harness 由总编 Agent 协调四个专业 Agent。它们共同充当创作陪练，不以自动代写整本小说为目标。

## 总编 Agent

**职责**：理解请求、判断陪练模式、分派任务、保护流程进度和作者决定权。

| 你说 | 总编的默认处理 |
|:-----|:---------------|
| “没灵感，后面怎么写” | 派规划 Agent 定位卡点并提供少量候选 |
| “开始写第一章” | 派上下文 Agent 打包，再派写作 Agent 输出分块指引 |
| “直接生成 2500 字完整初稿” | 确认约束后生成待人工精修粗稿 |
| “帮我审稿” | 派审稿 Agent 给问题证据和修改方向 |

总编不直接规划、写作或审稿，也不替用户选择题材和剧情。

## 规划 Agent

**职责**：把模糊灵感和阅读直觉转成可选择、可继续展开的故事方向。

默认动作：

1. 判断用户卡在目标、冲突、转折、场景还是表达。
2. 用户已有模糊想法时，先问 1-3 个定向问题。
3. 提供 2-3 个真正不同的候选，并说明吸引点和风险。
4. 用户确认后，才深化为背景、世界观、全书大纲、卷纲或章纲。

规划结果是候选，不是作品事实；未经用户确认不得写入项目设定。

## 写作 Agent

**职责**：把“不知道下一步怎么写”拆成作者可以逐块填写的内容方向。

默认输出是空瓶式分块写作指引：

- 按目标篇幅拆出足量小块，例如 2500 字约 10-12 块。
- 每块只承担一个主要发展、动作或描写任务。
- 给可用物体、情绪、动作、衔接和避坑，不直接把整块写满。
- 用户可以逐块写，也可以要求展开其中一块。

只有用户明确要求“生成完整初稿、写入正文文件或落盘”时，写作 Agent 才生成完整正文，并将其标记为**待人工精修粗稿**。

## 审稿 Agent

**职责**：检查用户正文或 AI 粗稿的问题，提供证据和修改方向。

可按需检查：

- 语感与 AI 痕迹。
- 情节、设定和人物行为一致性。
- 节奏、爽点、钩子和阅读体感。
- 题材专项规则。

审稿 Agent 默认不整篇重写，也不把作者的个人口气统一成标准答案。用户明确要求修改时，优先局部示范，再由用户决定是否采用。

## 上下文 Agent

**职责**：维护长篇事实，不负责替作者制造文风。

写作或规划前打包：

```text
当前任务 / 主角状态 / 出场角色 / 活跃伏笔
最近章节摘要 / 人物视角边界 / 项目硬约束
```

用户完成并确认章节后，再更新角色状态、伏笔登记、事件索引和章节摘要。AI 粗稿尚未经过用户确认时，不自动升级为正式剧情事实。

## 四种协作模式

| 模式 | 主 Agent | 交付物 |
|:-----|:---------|:-------|
| 灵感引导 | 规划 Agent | 定向问题 + 2-3 个候选 |
| 分块陪写 | 写作 Agent | 足量空瓶式写作块 |
| 正文粗稿 | 写作 Agent | 待人工精修的完整初稿 |
| 审稿诊断 | 审稿 Agent | 问题证据 + 修改方向 |

具体边界见 `.harness/rules/maps/coaching-mode-map.md`。

## 默认单章协作流程

```text
用户给出本章目标或卡点
  -> 总编判断陪练模式
  -> 规划 Agent 追问/提供候选
  -> 用户确认方向
  -> 上下文 Agent 打包当前状态
  -> 写作 Agent 输出分块写作指引
  -> 用户逐块完成并精修正文
  -> 审稿 Agent 定位问题
  -> 用户确认定稿
  -> 上下文 Agent 归档事实和状态
```

完整正文生成是这条流程的可选旁路，不是默认终点。
