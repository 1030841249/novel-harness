# Draft Output Map

> 用途：总编 Agent、写作 Agent 在“生成完整正文 / 写第 N 章并保存 / 续写并落盘”时加载。目标是连接项目骨架、粗稿文件和定稿归档，同时防止 AI 粗稿未经确认进入长期状态。

## 触发场景

| 用户意图 | 处理方式 |
|:---------|:---------|
| “开始写正文”“这一段怎么写”“下一段怎么接” | 先走分块写作指引，不视为落盘意图 |
| “直接写完整初稿”“生成正文”“写第 N 章并保存”“续写正文并落盘” | 视为“正文生成 + 落盘意图” |
| “先给方案”“不要写入文件”“只看效果” | 只输出方案或正文草稿，不创建项目文件 |
| “帮我写小说”但未确认方向 | 先走开书规划，不直接写正文 |
| 缺少项目名、题材、主角或当前项目指针 | 先补最少项目上下文，不创建正文 |

## 核心原则

- 明确要求生成完整正文并保存时，不要因为项目骨架缺失就永久暂停；应先完成“项目骨架初始化”，再恢复原写作任务。
- 初始化不是偷偷写入：执行前要在响应中说明“正在创建本地项目骨架/正文文件”，并保留原 `next_action`。
- 用户明确要求“只输出方案/不落盘”时，禁止创建目录或文件。
- 已存在正文文件时禁止覆盖；需要用户确认覆盖、追加，或另存为草稿文件。
- AI 生成并落盘的完整正文仍是“待人工精修粗稿”；用户确认定稿前，不更新章节摘要、事件索引、角色状态和伏笔。

## 项目骨架检查

进入正文前，检查：

```text
projects/{项目名}/
  设定/
  大纲/
  正文/
  状态/
  记忆/
    章节摘要/
```

缺失处理：

```text
有当前项目 + 用户明确要生成完整正文并保存
  -> 创建缺失目录
  -> 恢复 next_action：写作 Agent 生成正文

没有当前项目或项目仍是模板占位
  -> 询问最少必要信息
  -> 信息确认后再初始化骨架
```

## 正文文件定位

| 情况 | 默认路径 |
|:-----|:---------|
| 用户指定第 N 章 | `projects/{项目名}/正文/第N章.md` |
| 用户明确要求写第一章并保存，且正文目录为空 | `projects/{项目名}/正文/第1章.md` |
| 用户说续写，但未指定章节 | 先读取正文目录判断最新章；无法判断时询问章节号 |
| 目标文件已存在 | 不覆盖；询问追加、覆盖或创建 `第N章-草稿.md` |

## 恢复流程

```text
记录 next_action：
  action: write_full_draft
  project: {项目名}
  chapter: {第N章/待确认}
  target_words: {2000/2500/3000+/用户指定}
  output_path: projects/{项目名}/正文/{章节}.md

完成骨架/文件准备
  -> 调用上下文 Agent 打包最小记忆
  -> 调用写作 Agent 生成正文
  -> 写入 output_path
  -> 调用审稿 Agent 轻量检查
  -> 标记“待人工精修”，向用户返回粗稿和待确认变化
  -> 暂停归档，等待用户修改并确认定稿

用户确认定稿
  -> 调用上下文 Agent 更新章节摘要、事件索引、角色状态和伏笔
```

## 最小交互

只有以下信息缺失时才打断写作：

- 当前项目名无法确定。
- 章节号无法推断，且正文目录已有多个章节。
- 目标字数未确认。
- 目标正文文件已存在，需要确认处理方式。
