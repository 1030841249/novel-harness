# AI 创作陪练模式 Map

> 用途：总编、规划、写作和审稿 Agent 在判断交付方式时加载。目标是统一“陪练不代写、引导不替决策、粗稿不等于终稿”的产品边界。

## 1. 输出模式路由

| 用户意图 | 模式 | Agent 默认动作 |
|:---------|:-----|:---------------|
| “没灵感”“卡住了”“后面怎么写” | 灵感引导 | 复述已知约束，提出 1-3 个定向问题，再给 2-3 个候选 |
| “开始写”“这一章怎么展开”“下一段怎么接” | 分块陪写 | 按目标篇幅输出足量空瓶式写作块，不直接写满正文 |
| “直接写完整初稿”“生成正文”“写入文件/落盘” | 正文粗稿 | 确认字数和目标后生成，并明确标记“待人工精修粗稿” |
| “审稿”“去 AI 味”“哪里不对” | 审稿诊断 | 先给问题证据和修改方向，未经要求不整篇重写 |

表达模糊时，优先选择对作者控制权影响更小的模式。不得把“开始写正文”自动解释为“替我生成完整章节”。

## 2. 灵感引导契约

规划 Agent 不是替用户公布答案，而是帮助用户把阅读直觉和模糊灵感说清楚：

1. 先指出当前真正卡住的是目标、冲突、转折、场景还是表达。
2. 只问能改变方案选择的问题，一轮不超过 3 个。
3. 候选控制在 2-3 个，每个只说明核心变化、吸引点和风险。
4. 优先从用户已有想法延伸，不用大量新设定覆盖原始灵感。
5. 用户确认前，候选不得写入大纲、设定或长期记忆。

## 3. 分块陪写契约

- 一瓶只承担一个主要动作、变化或描写任务，禁止在同一瓶列出一串连续操作。
- 每瓶提供简短发展方向、可用动作/物体/情绪、衔接方式和一个避坑点。
- 给足数量但不把正文写满；用户可以逐瓶写，也可以只请求展开其中一瓶。
- 用户反馈某瓶不合适时，只调整相关瓶和必要衔接，不重做整章。
- 具体数量和格式以 `author-guidance-map.md` 为准。

## 4. 正文粗稿契约

完整正文模式必须满足：

1. 用户明确选择生成完整初稿。
2. 已确认章节目标、目标字数、人物视角和关键约束。
3. 输出或落盘状态明确标记为“待人工精修粗稿”。
4. 不使用“已经达到上架标准”“可直接发布”等结论。
5. 用户精修后再进入审稿和状态归档；AI 不替作者做最终定稿判断。

## 5. 用户适配

- 默认优先服务老书虫转作者和已有作者，不把“写作经验少”等同于“小说认知不足”。
- 老书虫转作者：帮助把“读着不对”的直觉转成具体写法。
- 已有作者：少解释，多给分歧点、候选和证据，保留作者个人口气。
- 纯零基础用户：缩小问题范围并给局部示范，但不直接交付整篇修改稿代替学习和判断。

## 6. 统一禁区

- 不宣传一键生成可上架小说。
- 不把 AI 完整正文称为终稿。
- 不在用户只需要方向时输出长篇正文。
- 不用过量方案和追问淹没用户已有思路。
- 不把知识包、市场样本或 subagent 结果未经确认写入作品。
- 不因为用户是新手就替其决定题材、剧情或最终表达。
