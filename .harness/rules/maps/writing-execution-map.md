# Writing Execution Map

> 用途：写作 Agent 按需加载的正文执行规则图。Agent 本体只保留入口。

## 默认模式

输出模式统一由 `.harness/rules/maps/coaching-mode-map.md` 判断；本 Map 不重复维护触发词。分块指引格式见 `.harness/rules/maps/author-guidance-map.md`。

## 场景三维度织入

| 维度 | 写什么 | 要点 |
|:-----|:-------|:-----|
| 发生 | 事情本身出现 | 1-2 句，有具体动作或变化 |
| 感知 | 主角注意到的细节 | 视觉之外至少补触觉、听觉、嗅觉或身体细节 |
| 反应 | 身体如何回应 | 手、眼、呼吸、姿势、动作，不用情绪标签 |

规则：三个维度织进同一个连续镜头，不拆成三段说明。

## 人物反应胶水

完整正文模式的交付物仍是待人工精修粗稿。信息点之间衔接发硬时，可以按需加入动作、停顿、感知、环境或口语反应，但不设固定数量和顺序。

- 原文已有自然反应时不要继续补齐。
- 相邻镜头不要重复同一种反应组合。
- 反应必须来自人物经历和现场压力，不能把通用例子套给所有题材。
- 详细诊断与修改方式统一加载 `.harness/skills/human-linguistics/rules/去AI味最小修改指南.md`。

## 环境与吐槽边界

- 环境优先使用与当前动作、风险或情绪直接相关的少量物体，不做平均扫描。
- 吐槽从当前动作、物体、人物经历和关系中产生，不为搞笑额外搭建新场景。
- 这两项是可选手段，不是每个镜头的必填项。

## 行动清单边界

一个写作块只保留一个**主要目标**，但可以包含完成目标所需的连续动作、人物反应和结果。限制的是“把多个未来计划并列报菜名”，不是正常动作链。

- 当前真正执行的事写具体，尚未执行的计划只保留最相关的一项。
- 多个独立目标按时间或因果拆到后续写作块。
- 不为避免并列而强拆成连续极短句；句子节奏仍需符合场景和人物口气。

## 对话权力与议程

| 项 | 规则 |
|:---|:-----|
| 议程 | 每个主要角色进入对话前都要知道自己想得到什么 |
| 权力 | 掌控者话短，被动者话多 |
| 压制 | 主角亮底牌、心死、压制时尽量短，不额外解释 |
| 信息 | 世界观和规则用角色立场包住，不机械说明 |
| 群聊/弹幕 | 普通人反应 -> 懂行者分析 -> 特殊身份者改变认知 |

## 小节偏短诊断

低于目标字数时按顺序补：

1. 情节点是否不足，先回细纲补真实事件。
2. 子事件是否缺“发生 + 感知 + 反应”。
3. 对话是否缺有议程的交锋。
4. 是否缺配角/群众/频道反应。
5. 是否缺阻碍、意外反应、新发现、简短回忆或连锁后果。

禁止用心理解释、设定说明、风景、重复情绪、无功能动作凑字。

## 段落与句子

| 检查 | 标准 |
|:-----|:-----|
| 单段 | 一个镜头拍点或动作单元 |
| 换段 | 新动作、新物件、新线索、新对话出现 |
| 长度 | 单段超过 60 字优先拆；单句超过 35-45 字优先拆或删修饰 |
| 节奏 | 不连续堆同长度短段，不连续长句拖慢 |

## 微观拼接感自检

命中以下情况，标记为需要人工精修，不要机械补齐反应链：

- 每句话都在推进剧情，读起来像大纲扩写。
- 信息点齐全，但人物没有下意识动作、误判、停顿或口语反应。
- 主角遇到异常后过快冷静，直接进入分析。
- 关键节点只有“看见 -> 判断 -> 接受”，没有身体和环境承接。
- 段落之间像方块拼接，缺少动作、视线、物件或现场声音过渡。

具体如何修改以“去 AI 味最小修改指南”为唯一规则源。
