# Perspective Boundary Map

> 用途：规划 Agent、写作 Agent 在大纲设定和正文生成前按需加载。目标是约束“从谁的视角理解、判断和表达”，避免作者视角、读者视角、角色视角混用导致内容偏离。

## 视角三层

| 层级 | 问题 | 用途 |
|:-----|:-----|:-----|
| 人物视角 | 本次输出借用哪个人物/观察者身份判断？ | 规划、审稿、设定推演 |
| 叙事视角 | 正文镜头跟着谁？ | 正文生成、续写 |
| 信息边界 | 这个视角能知道什么？ | 防止剧透、越界判断、上帝视角 |

写作或大纲设定前必须先确定：

```text
本次人物视角：
正文叙事视角：
可用信息：
禁止越界信息：
```

## 视角类型

| 视角 | 能做什么 | 禁止什么 | 适用场景 |
|:-----|:---------|:---------|:---------|
| 读者视角 | 判断吸引力、期待、爽点、困惑点 | 代替角色做决策；直接写入正文内心 | 审稿、章尾钩子、卖点检查 |
| 作者视角 | 设计结构、伏笔、节奏、因果、长期设定 | 直接进入正文旁白暴露幕后设计 | 大纲、世界观、长线伏笔 |
| 主角视角 | 感知现场、做选择、形成有限判断 | 知道未经历事件、反派动机、全局真相 | 正文主叙事、代入感场景 |
| 普通 NPC 视角 | 展示底层认知、恐慌、误解、流言 | 理解高层秘密、准确解释体系规则 | 群众反应、聊天频道、世界质感 |
| 重要 NPC 视角 | 展示势力判断、专业认知、局部真相 | 知道作者全局安排；无来源地看透主角 | 反派、导师、高层、队友视角 |
| 世界背景视角 | 交代时代、制度、环境压力 | 变成百科设定说明；替角色总结情绪 | 卷首设定、转场、宏观压力 |

## 使用规则

### 规划/大纲

- 可以使用作者视角设计全局，但输出给写作 Agent 时要标明哪些信息不能进入正文。
- 设计章纲时要标明本章主要叙事视角，默认优先主角视角。
- 如果需要 NPC 视角，必须说明它的功能：制造信息差、展示误解、放大震惊、制造压力、补充世界质感。
- 普通 NPC 只能表达普通认知；重要 NPC 可以有专业判断，但必须有信息来源。

### 正文

- 正文默认使用主角有限视角，除非大纲明确要求切视角。
- 切换视角必须有功能：制造信息差、展示后果、强化期待、交代主角无法看到的变化。
- 切视角不要在平淡处切，优先在悬念点、危机点、反应点切。
- 同一场景不要频繁跳进多个角色内心；优先用动作、表情、对话表现其他角色。
- 作者视角信息不能伪装成主角判断。

## 视角越界信号

| 信号 | 问题 |
|:-----|:-----|
| 主角刚见到人就判断对方性格、来历、真实动机 | 主角视角越界 |
| 普通路人准确解释世界底层规则 | 普通 NPC 视角越界 |
| 重要 NPC 无来源地看穿主角金手指 | 重要 NPC 视角越界 |
| 旁白提前告诉读者后续必然走势 | 作者视角泄漏 |
| 正文突然总结“这意味着世界格局改变” | 作者/读者视角混入正文 |
| 大纲把读者期待写成角色动机 | 读者视角和角色视角混淆 |

## 输出模板

### 章纲视角栏

```text
视角配置：
- 人物视角：作者视角 / 读者视角 / 角色视角
- 正文叙事视角：主角 / 普通 NPC / 重要 NPC / 多视角
- 本章可公开信息：{读者和叙事视角可以知道的内容}
- 本章禁止泄露：{作者知道但正文不能写出的内容}
- NPC 视角用途：{如无则写“无”}
```

### 正文写前视角栏

```text
当前镜头跟随：
角色可知道：
角色不能知道：
读者应知道：
读者暂时不能知道：
切视角条件：
```

## 与角色知识边界的关系

本 Map 决定“用哪个视角写”；`.harness/skills/plot-review/rules/角色知识边界.md` 决定“该视角能知道什么”。两者同时命中时，先遵守角色知识边界。
