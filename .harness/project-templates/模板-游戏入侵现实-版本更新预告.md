# 项目模板：游戏入侵现实 · 版本更新预告

> 适用于“现实被游戏规则逐步侵蚀 + 主角提前看到版本更新提示”的长篇网文。
> 重点不是开局全球崩坏，而是用灰度测试、版本日志、局部异常和信息差推动故事。

## 二、题材定位

这个模板适合写：

```text
现实仍有秩序
→ 局部出现异常
→ 主角提前看到版本更新提示
→ 主角拆解提示并提前准备
→ 更新生效后验证判断
→ 获得资源、信息差或生存优势
→ 下一次版本更新带来更大风险
```

核心爽点不是“系统替主角解题”，而是：

- 主角比别人更早知道危险。
- 主角能从模糊提示里拆出关键条件。
- 普通人和官方都在后知后觉，主角提前一步验证、布局、拿资源。
- 每次更新都带来新的规则、新的风险和新的机会。

## 三、世界基础

故事发生在现代现实社会。前期不要直接写全球崩坏，先让世界保持“还能正常运转”的表象。

早期异常建议从低烈度开始：

- 城市里的小动物异常：流浪猫、野狗、老鼠、鸟类、观赏鱼。
- 日常但偏僻的地点异常：地铁口、地下车库、夜跑公园、旧商业街、城中村、废弃厂房。
- 官方初期按现实逻辑处理：动物伤人、未知传染病、非法实验、恶性袭击、网络谣言。
- 普通人没有系统提示，只能从监控、新闻、现场封锁、亲身遭遇中发现不对劲。

世界变化要像灰度发布：

```text
小范围测试
→ 城市局部异常
→ 大型动物异变
→ 异兽投放
→ 异常区域成型
→ 安全区/职业/组织/跨城机制逐步出现
```

## 四、主角适配

主角可以是普通人，但最好有一种能解释“他比别人更快读懂更新提示”的现实能力。

适合职业：

- 程序员：熟悉版本日志、需求文档、错误提示。
- 测试工程师：擅长找边界条件和复现异常。
- 网安从业者：擅长看漏洞、权限、风险窗口。
- 游戏策划/运营：熟悉活动机制、数值投放和版本节奏。
- 老书虫普通青年：更快接受世界异常，但不能把小说经验当攻略。

主角优势建议包括：

- 能拆解更新时间、影响范围、风险提示、条件和代价。
- 遇到异常先验证、记录、推演，不是无脑冲。
- 有一点现实准备能力，如健身、急救、工具使用、地图熟悉。
- 能把信息差转化为资源差、位置差、时间差。

主角短板必须保留：

- 没有开局无敌战斗力。
- 没有强大人脉和资源。
- 第一次面对生死危机可以害怕、手抖、判断变慢。
- 版本提示不是攻略，主角也会误判。

### 4.1 职业经验型主角（可选）

如果主角拥有程序员、测试工程师、网安从业者或资深网文读者等经历，可以把职业经验转化为观察和决策方式，但不能把它写成固定人格模板：

- 技术职业可以带来验证意识、边界条件思维和对“版本漏洞”的敏感，不等于绝对冷静。
- 阅读经验可以帮助主角联想到常见套路，不等于提前知道世界答案。
- 面对异常时允许害怕、迟疑、嘴硬或兴奋，具体组合由人物性格和现场压力决定。
- 是否报警、公开或独自验证，必须根据人物处境、风险和利益判断，不能由模板替用户决定。
- 生活感从用户确认的职业、收入、家庭、通勤和人际经历中取材，不默认使用加班、工位或同事梗。

关键节点不要直接跳过验证过程：主角先注意异常，再做符合其经历的低成本确认，最后形成暂时判断。反应种类和先后顺序不固定，也不要求每次都加入误判或吐槽。

## 五、金手指设计

金手指是“版本更新提示”，不是完整系统面板。

提示出现时可以有轻微异象，例如电子提示音、视野前方浮现半透明文字、手机/眼前出现无法录屏的提示。重点是“像版本日志”，不要写成唠叨旁白。

版本提示的载体和视觉样式必须在项目设定中确认，不由公共模板固定：

| 配置项 | 可选方向 |
|:-------|:---------|
| 出现载体 | 视野悬浮、手机界面、实体终端、声音提示或其他 |
| 视觉样式 | 颜色、字体、透明度、是否遮挡现实视野 |
| 操作方式 | 念头、触碰、语音、不可操作或其他 |
| 感知边界 | 闭眼是否可见、他人能否看见、能否截图或记录 |

初次出现时，先让角色通过现场动作确认提示的感知边界，再逐步暴露规则。任何颜色、字体和界面风格都必须由当前项目确认，公共模板不提供默认表现。

### 5.1 公告条目写法

版本更新和补丁说明建议用短条目，不写成长篇公告。格式上让读者一眼抓住：什么时候发生、哪里发生、有什么变化、主角能抢什么窗口。

基础形态：

```text
【版本 0.1.0】

【一、{生效时间}，{异常/机制}将在{大致范围}出现】

【二、{地点类型A}、{地点类型B}、{地点类型C}，更容易出现{异常/资源/风险}】

【三、{击杀/探索/完成条件}后，将出现{新增资源/新机制}】

【四、当前为{测试/小版本/区域更新}，{数量/范围/规则}有限且不稳定】
```

紧急补丁可以更短、更像修复预告：

```text
【已知问题（修复预告）】

【一、修复{当前版本可被利用的规则漏洞}】

【二、修复后，{收益/掉落/安全窗口}将从必定变为概率】

【三、{刷新数量/攻击性/风险等级}小幅上升】

【四、以上修复将在{时间}后生效】
```

### 5.2 资源说明写法

新增资源、道具、结晶、材料第一次出现时，再使用资源说明格式。资源说明可以帮助主角识别目标，但不能把攻略喂完。

```text
【新增资源说明】

【{资源名}】

【说明：{资源从哪里出现/大致如何识别}】

【外观：{颜色/大小/触感/形态}】

【效果：{最基础作用，不写完整数值和最优用法}】
```

可选提示维度：

- 大版本更新：提前 1-3 天，开启重要机制。
- 小版本更新：提前 12-24 小时，改变局部规则。
- 区域更新：只提示主角所在城市或附近区域。
- 紧急补丁：时间更紧，内容更短，适合制造压迫。

金手指边界：

- 只能提前看到即将发生的版本变化，不能看到完整未来。
- 可以显示地点类型或大致范围，例如地下车库、废弃厂房、荒僻公园，但不显示具体坐标。
- 不显示怪物数量、精确藏身点、最优路线、战斗打法或安全撤离方案。
- 不显示谁会死亡。
- 不提供完整攻略。
- 不保证主角能完全理解提示含义。
- 提示措辞可能有陷阱，例如“低级异常”不等于安全。
- 可以显示新资源的基础样式和最低限度说明，但不能给具体产出点、概率表或完整步骤。

提示可以说清目标类型，但必须留下判断空白。它可以告诉主角“人少区域更容易刷新，旧小区地下车库、废弃厂房、停工工地、废弃楼房、荒僻公园、垃圾中转站更危险”，但不能告诉他本地具体哪一处已经刷新、哪只怪躲在哪里、该怎么杀、什么时候撤。

## 六、力量体系

推荐前期不要写全民数据面板。普通人没有属性栏、血量、经验条、系统公告或版本面板。

更稳的力量线：

```text
击杀异常生物
→ 解剖或处理尸体
→ 获取特殊资源
→ 吸收/使用后获得体感强化
→ 通过实战和后期检测确认强化水平
→ 围绕资源产生官方管控、黑市、民间猎杀队和势力争夺
```

常用资源设计：

- 源核：异常生物体内凝结的强化资源。
- 异化材料：可用于武器、防具、药剂或检测设备。
- 区域凭证：进入异常区域或活动区域的条件。
- 规则碎片：用于理解版本机制或解锁更高权限。

边界：

- 资源必须有获取成本，不自动掉落到地上。
- 如果写源核，建议让它在异常生物胸腔附近凝结，需要处理尸体才能取出。
- 早期普通人就算击杀异常生物，也未必会想到处理尸体、寻找资源。
- 初期强化以体感反馈为主，不写成全民面板。
- 后期可以出现官方检测仪器，但那是现实设备，不是系统。

## 七、故事主循环

```text
更新前收到版本提示
→ 主角拆解提示关键词
→ 提前做准备或布局
→ 版本降临
→ 现实异常逐步发生
→ 官方或普通人后知后觉
→ 主角验证判断并争夺资源
→ 发现提示没有说全，或自己理解错了部分内容
→ 新版本提示出现，危机升级
```

每一轮循环都要有三件事：

1. 读者看懂这次更新改变了什么。
2. 主角通过准备获得可见收益。
3. 章尾留下下一次更新或更深规则的压力。

## 八、黄金三章模板

### 第 1 章：版本提示出现

必须完成：

- 主角在现实生活里收到异常版本提示。
- 提示内容短、冷、像日志，但指向现实危险。
- 主角产生怀疑，并做出第一次低成本验证。
- 章尾让读者知道：提示可能是真的。

### 第 2 章：提前准备与第一次异常

必须完成：

- 主角根据提示做准备，如避开地点、买工具、查路线、观察新闻。
- 异常在现实中出现，但普通人还无法理解。
- 主角第一次靠信息差避险或拿到优势。
- 章尾抛出更明确的资源或危险。

### 第 3 章：第一次闭环

必须完成：

- 主角完成第一次“提示 → 准备 → 验证 → 收获”闭环。
- 收获必须可见：资源、身体强化、证据、位置优势、官方信息差。
- 主角意识到这不是恶作剧，而是长期版本更新。
- 章尾出现下一次更新提示或更大危机。

## 九、前 30 章推进

```text
1-5章：
立版本提示、立第一轮异常、立主角分析优势，完成第一次资源闭环。

6-10章：
扩大异常影响范围，让主角发现提示有遗漏或陷阱。

11-15章：
引入官方封锁、网络传言、第二类异常资源，形成普通人与主角的信息差。

16-20章：
出现稳定异常区域或小型副本感场景，但不要直接全民面板化。

21-25章：
主角开始接触其他知道异常的人，出现合作、交易或争夺。

26-30章：
引出更大的版本机制，如城市区域更新、安全点、检测设备、组织势力。
```

## 十、长期发展方向

前期：

- 写个人信息差和局部异常。
- 让主角从验证提示到稳定利用提示。
- 官方和普通人逐渐意识到异常存在。

中期：

- 写异常区域、资源争夺、官方管控、民间组织。
- 主角从个人幸存者变成团队核心。
- 版本更新开始影响城市秩序。

后期：

- 扩大到跨城、跨区域、全球机制。
- 揭示版本更新背后的更高规则。
- 主角从“读取版本的人”成长为“理解版本并尝试影响版本的人”。

## 十一、写作边界

允许：

- 现实秩序缓慢变质。
- 官方前期理性但信息不足。
- 主角害怕、试错、误判。
- 信息差带来收益，但收益需要冒险验证。
- 程序员、测试、网安、游戏策划等身份服务剧情。

禁止：

- 开局直接全球崩坏。
- 普通人一开始就人人有面板。
- 版本提示变万能攻略。
- 版本提示写成长篇说明书或百科词条。
- 主角开局无敌或硬刚怪物。
- 主角有健身/格斗基础就写成专业战斗高手。
- 大段技术说明挤占剧情。
- 复杂数值堆叠压过选择、代价和反馈。
- 把“老书虫经验”写成知道标准答案。
- 资源说明提供精确定位、产出概率、击杀步骤和撤退方案。

## 十三、自检清单

```text
版本提示是否只给信息差，而不是完整攻略？
公告条目是否短、冷、醒目，而不是长篇解释？
第一轮异常是否足够现实、低烈度、可信？
主角优势是否来自分析和准备，而不是凭空无敌？
普通人为什么不知道、官方为什么慢一步，是否解释清楚？
每次更新是否带来明确变化、风险和收益？
资源获取是否有成本？
是否保留了误判、遗漏和代价？
```
